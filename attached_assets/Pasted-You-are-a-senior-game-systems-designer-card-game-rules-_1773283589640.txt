PROJECT CONTEXT
==================================================

Compost Heroes is a card game with:
- 34 hero cards
- 17 action cards
- card fronts and backs
- card facts, effects, and layers
- a win condition based on collecting one hero from each layer

Important core rule:
The game must understand the meaning of each card’s effect and implement it automatically.
Example:
- If a played card says “draw 1 card,” the engine must automatically draw 1 card.
- If a card causes another player to discard, steal, swap, reveal, protect, or otherwise change game state, the system must apply that effect correctly.

The final system must support:
- 2 to 4 players
- online browser play
- facilitated play-session mode
- independent autonomous play mode
- exact implementation of card effects
- AI/rules engine enforcement of legal gameplay

==================================================
ENGINEERING STRATEGY
==================================================

Use a low-entropy, implementation-first approach suitable for ChatGPT reasoning and Replit development.

Design the game in layers:

1. RULE EXTRACTION LAYER
   - Read and normalize the rules
   - Identify setup, turn structure, action timing, targeting logic, win condition, and exceptions
   - Extract card effect verbs and state changes

2. CARD DATA LAYER
   - Convert all cards into a structured JSON schema
   - Separate display text from executable effect logic
   - Recommend a schema that can scale as more cards are added later

3. EFFECT INTERPRETATION LAYER
   - Create a rules/effects system that maps card text to executable actions
   - Use structured effect objects where possible
   - Distinguish between:
     - immediate effects
     - targeted effects
     - conditional effects
     - passive or persistent effects
     - triggered effects
     - protection or override effects
   - Include a fallback method for handling edge-case or unusually worded cards

4. GAME STATE LAYER
   - Define full game state structure, including:
     - players
     - hands
     - decks
     - discard pile
     - in-play cards
     - collected layers/heroes
     - current turn
     - phase
     - pending choices
     - effect queue / stack if needed
     - winner state

5. GAME ENGINE LAYER
   - Define turn flow and action resolution
   - Show how legal actions are validated
   - Show how effects are executed automatically
   - Show how the engine checks for win condition after each relevant state change

6. UI/UX LAYER
   - Design a browser-based interface
   - Support up to 4 players
   - Make the game easy to follow during live hosted sessions
   - Make card effects visually understandable
   - Include prompts when players must choose targets or make decisions
   - Include educational flavor without cluttering gameplay

7. MODE DESIGN LAYER
   - Facilitator Mode:
     - one host can guide the game
     - easy visibility into all players and board state
     - useful for teaching and playtesting
   - Standalone Mode:
     - players can play without you present
     - system teaches the flow
     - system enforces the rules automatically
     - include onboarding/tutorial recommendations
